# 코드 품질 검증 및 커밋 표준 절차 가이드

> **문서 ID**: PB-DEV-001  
> **최초 작성일**: 2026-09-11  
> **최종 수정일**: 2026-09-11  
> **버전**: v1.0.0  
> **상태**: Active  

---

# 목적
코드 변경 사항을 Git 저장소에 커밋하기 전 일관된 품질을 확보하고, 자동화된 Git Hook 검증을 통해 빌드 실패 및 컨벤션 불일치를 미연에 방지하기 위함입니다.

---

# 언제 사용하는가
- 새로운 기능 구현, 버그 수정, 문서 작성 등 작업이 완료되어 Git 커밋을 생성할 때
- Pull Request를 올리기 전 로컬 브랜치를 정리할 때

---

# 필요한 입력
- 변경 및 수정된 소스 파일들
- 커밋 메시지 (작업 목적과 변경 사항 요약)

---

# 작업 절차

## Step 1: 셀프 검증 및 로컬 테스트
1. 작업한 파일의 문법 오류 및 불필요한 콘솔 로그(`console.log`), 디버그 코드를 정리합니다.
2. 터미널에서 전체 프로젝트 린트(`pnpm lint`) 및 빌드(`pnpm build`)가 성공하는지 확인합니다.

## Step 2: 변경 파일 선별 스테이징
1. `git status`로 변경된 파일 목록을 확인합니다.
2. 현재 작업 단위에 해당하는 파일만 선별하여 `git add [파일명]`으로 스테이징합니다.
   - 불필요한 임시 파일이나 의도치 않은 설정 파일이 스테이징되지 않도록 주의합니다.

## Step 3: 커밋 메시지 작성
커밋 메시지는 반드시 **요약 + 상세 설명** 형식으로 작성합니다.

### 커밋 메시지 구조
```
<타입>: <요약 (한 줄, 50자 이내)>

## <섹션 제목>

- <변경 항목 1>
- <변경 항목 2>
  (세부 내용은 들여쓰기로 표현)
```

### 커밋 타입
| 타입 | 사용 시점 |
| :--- | :--- |
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 기능 변경 없이 코드 구조 개선 |
| `style` | 스타일/디자인 변경 (기능 무관) |
| `docs` | 문서, Knowledge, Playbook 작성/수정 |
| `chore` | 빌드, 설정, 패키지 관련 변경 |
| `test` | 테스트 코드 추가/수정 |

### 멀티라인 커밋 작성 방법
긴 본문이 포함된 커밋은 임시 파일에 메시지를 작성한 뒤 `-F` 옵션으로 사용합니다:
```bash
# 1. 메시지 파일 작성
# 2. git commit -F <메시지파일경로>
```

## Step 4: 커밋 실행 및 lint-staged 자동 검증
1. `git commit -F <메시지파일>` 또는 `git commit -m "타입: 요약"` 을 실행합니다.
2. `.husky/pre-commit`에 의해 `lint-staged`가 자동으로 실행되며 스테이징된 파일에 대해 `eslint --fix`를 수행합니다.
3. 모든 검증을 통과하면 정상적으로 커밋이 완료됩니다.

---

# 판단 기준
- **커밋 분할 기준**: 하나의 커밋에는 단일 목적의 변경 사항만 포함합니다. (예: 기능 추가와 무관한 포맷팅 리팩토링은 분리)
- **자동 수정 처리**: `eslint --fix`에 의해 자동으로 포맷이 교정된 경우, 추가 작업 없이 커밋에 포함됩니다.

---

# 예외 상황
- **린트 오류로 커밋 중단 (Pre-commit hook failed)**:
  - 원인: 자동 수정이 불가능한 문법 규칙 위반 (예: 사용하지 않는 변수 선언, 타입 불일치 등)
  - 대처: 터미널의 에러 로그를 확인하여 해당 파일의 코드를 직접 수정한 뒤, 다시 `git add` 후 커밋을 재시도합니다.
- **긴급 핫픽스 시 Hook 우회 필요 여부**:
  - 원칙: 어떠한 경우에도 `--no-verify` 플래그로 훅을 임의 우회하지 않습니다.

---

# 금지사항
- **금지 1**: `git commit --no-verify`를 사용하여 품질 검증 단계를 무단으로 건너뛰는 행위
- **금지 2**: 관련된 테스트가 깨지거나 빌드가 되지 않는 상태에서 커밋을 강행하는 행위
- **금지 3**: `git add .`으로 의도치 않은 로컬 환경 설정 파일이나 키 파일을 무차별 커밋하는 행위

# 결과물 형식
- 올바른 컨벤션의 Git 커밋 로그
- 오류 없이 클린하게 통과된 Pre-commit 실행 결과
